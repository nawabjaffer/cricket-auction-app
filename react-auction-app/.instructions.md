# Cricket Auction SaaS — Agent Instructions

## Project Overview

This is a React + TypeScript cricket auction management app being transformed into a multi-tenant SaaS platform. It uses Firebase Realtime Database for persistence and cross-device sync, Zustand for state management, and Framer Motion for animations.

## Tech Stack

- **Framework**: React 19 + TypeScript 5.9
- **Build**: Vite 7
- **State**: Zustand 5 (single `auctionStore.ts`)
- **Data Fetching**: TanStack React Query 5 + Firebase RTDB SDK
- **Styling**: Tailwind CSS 4 + vanilla CSS modules
- **Animation**: Framer Motion 12
- **Routing**: React Router DOM 7
- **Deployment**: Firebase Hosting (`e-auction-store.web.app`)
- **Git Branch**: `EPL-Tournament`

## Architecture

```
src/
  components/    ← React UI components (View layer)
  config/        ← App configuration + tournament configs
  contexts/      ← React contexts (TenantContext — to be created)
  controllers/   ← Business logic controllers (MVC pattern)
  hooks/         ← Custom React hooks (bridge between View and State)
  models/        ← Domain models, DTOs, response types
  pages/         ← Route-level page components
  repositories/  ← Data access layer (repository pattern)
  services/      ← External service integrations (Firebase, Google Sheets, etc.)
  store/         ← Zustand stores (auctionStore, liveStreamingStore)
  types/         ← TypeScript type definitions
  utils/         ← Shared utility functions
```

## Auth System

- **Admin**: Email-only login → `authService.ts` → checks RTDB `admin/accounts/{emailKey}` → session in localStorage (24h expiry)
- **Team Bidding**: Hardcoded credentials in `auth.ts` (8 teams). `MobileBiddingLivePage` generates dynamic credentials from team data.
- **SaaS migration**: Add password field (SHA-256 + salt), scope accounts to `tenants/{tenantId}/admin/accounts/`

## Data Flow

1. **Player data**: Google Sheets → `useInitialData()` hook → Zustand store. Admin can also edit players in AdminPanel → saved to Firebase `auction/adminPlayers`.
2. **Auction state**: Desktop app writes to Firebase `auction/currentState` via `realtimeSync.broadcastState()`. Mobile devices read it via `realtimeSync.listenForStateChanges()`.
3. **Bidding**: Mobile submits to `auction/mobileBids`. Desktop reads via `realtimeSync.listenForMobileBids()`.
4. **Persistence**: Sold/unsold players saved to Firebase via `auctionPersistence`. Restored on page load via `useAuctionDataLoader()`.

## Module-Level Flags (Performance Guards)

Three module-level `let` flags prevent redundant Firebase fetches on SPA route changes:
- `_globalPreloadComplete` in `src/hooks/useData.ts` — image preload
- `_globalDataLoaded` in `src/hooks/useData.ts` — Firebase data fetch
- `_globalRestoreComplete` in `src/hooks/useAuctionDataLoader.ts` — auction data restore

These must be reset when switching tenants (add reset function for SaaS).

## SaaS Migration Plan

See `docs/SAAS_ARCHITECTURE.md` for the complete plan. Key phases:

1. **Phase 1**: Multi-tenant foundation — tenant path helper, context provider, scoped routes
2. **Phase 2**: Franchise auth — login page with tournament selector + email/password
3. **Phase 3**: Player lifecycle — trials, match fixtures, squad selection
4. **Phase 4**: Match scoring — generic adapter pattern (CricHeroes, manual entry)

## Coding Conventions

- **Services**: Singleton classes with `initialize(db)` pattern. Import instances (e.g., `import { realtimeSync } from './realtimeSync'`)
- **Hooks**: Custom hooks prefixed with `use`. Barrel-exported from `hooks/index.ts`
- **Components**: Each in own folder with `ComponentName.tsx` + `ComponentName.css` + `index.ts`
- **Types**: Centralized in `src/types/index.ts`. Premium types in `src/types/premium.ts`
- **CSS**: Mix of Tailwind utilities and vanilla CSS. Component-specific CSS files colocated
- **Firebase RTDB**: Use `ref()`, `set()`, `get()`, `onValue()` from `firebase/database`. Always check `snapshot.exists()` before `.val()`
- **Error handling**: Try/catch in async operations. Log with `console.error('[ServiceName]', error)` prefix

## Important Notes

- Firebase config is hardcoded in `realtimeSync.ts` and `firebase.ts` (same project: `e-auction-store`)
- `realtimeSync.ts` initializes Firebase as a named app (`'realtime-sync'`) to avoid conflicts
- The Zustand store uses `persist` middleware with localStorage — tenant-scoped keys needed for SaaS
- Google Sheets integration is manual-only (no auto-sync) — triggered from AdminPanel "Import from Sheets" button
- Image compression (300x300 JPEG thumbnails) is applied before saving to Firebase RTDB to stay under write limits
- The `config/index.ts` already has `tournamentConfigs` map and `getTournamentConfig()` — wire these to dynamic tenant DB data
