# Players and Registration Guide

## Manage the player pool

Open **Admin → Players** to review the tournament's player list. Search for a player before adding a record to avoid duplicates. Keep each player's name, role, base price, contact details, and sport-specific statistics accurate. Use the available import/export controls for bulk updates and review any validation report before applying imported records.

Removed players are available in the **Trash** subsection when supported. Restore a player if they were removed by mistake; permanently remove records only when the event owner has approved it.

## Configure public registration

1. Open **Admin → Registration form**.
2. Set the form title, description, enabled state, and fields required for this tournament.
3. Save and open the public registration link in a private browser window to test it as a player.
4. Submit a test only if the tournament's process allows test entries; otherwise, stop before final submission.
5. Review incoming registrations in Admin and reconcile them with the player pool before the auction.

The public form may be unavailable while registration is disabled or when the tournament tenant is inactive.

## Player identity and photos

- Match on stable identifiers such as registration ID or verified contact information, not name alone.
- Check image orientation and crop before saving a player photo.
- Use a clear, consented image suitable for the event's public displays.
- Correct player records at their source before importing again; repeated imports can create duplicates if identity fields differ.

## Before auction day

Filter the pool by role/category, confirm base prices and eligibility, inspect duplicate warnings, and export a backup. After the auction, use the sold/unsold results rather than manually changing a player's sale status in the player editor.
